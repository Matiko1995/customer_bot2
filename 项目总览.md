总览                                                                                  
  现在还是“单仓库、单 Nuxt/Nitro 应用、多职责混合”架构。                                
                                                                                        
  核心入口文件和目录：                                                                  
                                                                                        
  - 启动与构建脚本：package.json                                                        
  - 页面层：pages                                                                       
  - API 层：server/api                                                                  
  - 后端业务层：server/lib                                                              
  - 前端挂件 SDK：src/widget.ts                                                         
  - RAG/资料导入相关：server/lib/ingestion、server/lib/rag                              
                                                                                        
  可以粗略画成：                                                                        
                                                                                        
  Nuxt 页面 + Widget SDK + Nitro API + RAG/导入流水线 + 存储适配层                      
                                                                                        
  这几部分目前都在一个项目里。                                                          
                                                                                        
  1. 访问链路                                                                           
  用户现在能访问的前端入口有三组：                                                      
                                                                                        
  - 官网页：pages/index.vue                                                             
  - 管理后台页：pages/admin                                                             
  - 租户只读页：pages/tenant                                                            
                                                                                        
  如果是外部网站挂件模式，链路是：                                                      
                                                                                        
  1. 客户站点加载 customer-bot.js                                                       
     入口在 src/widget.ts                                                               
  2. 挂件启动后先请求运行时配置                                                         
     对应 server/api/embed/config.get.ts                                                
  3. 用户发消息时，请求聊天接口                                                         
     对应 server/api/chat.post.ts                                                       
  4. 留资时，请求联系接口                                                               
     对应 server/api/contact.post.ts                                                    
                                                                                        
  也就是说，前台访问链已经不是纯静态网站，而是：                                        
                                                                                        
  页面/挂件 -> Nitro API -> 后端业务逻辑 -> 存储层                                      
                                                                                        
  2. 聊天链路                                                                           
  当前聊天链的真正核心在 server/lib/chat.ts。                                           
                                                                                        
  现在内部流程大致是：                                                                  
                                                                                        
  1. api/chat.post 收到 tenantId + message + sessionId + attachments                    
  2. chat.ts 解析租户                                                                   
     通过 server/lib/tenant-resolver.ts                                                 
  3. 加载或创建 session                                                                 
  4. 保存用户消息                                                                       
  5. 做问题分类                                                                         
     通过 server/lib/rag/query-classifier.ts                                            
  6. 进入三选一路径：                                                                   
      - structured                                                                      
        FAQ/价格/联系问题，走 server/lib/rag/structured-fast-path.ts                    
      - rag                                                                             
        文档问题，走 server/lib/rag/retriever.ts -> server/lib/rag/answer-chain.ts      
      - general_fallback                                                                
        资料未命中且非价格问题，走 server/lib/rag/fallback-chain.ts                     
  7. 保存 assistant 消息                                                                
     现在会带上：                                                                       
      - answerSource                                                                    
      - credentialSource                                                                
      - citations                                                                       
      - retrievalConfidence                                                             
  8. 保存 usage 记录                                                                    
     现在能区分：                                                                       
      - 租户自有模型                                                                    
      - 平台共享模型兜底                                                                
                                                                                        
  这条链已经不是简单问答了，已经混合了：                                                
                                                                                        
  会话管理 + 路由策略 + RAG 检索 + LLM 调用 + provenance 记账                           
                                                                                        
  3. RAG / 资料导入链路                                                                 
  这部分是你这次改造的新增主线，已经形成独立子系统。                                    
                                                                                        
  入口 API 在：                                                                         
                                                                                        
  - server/api/admin/tenants/[tenantId]/sources.get.ts                                  
  - server/api/admin/tenants/[tenantId]/sources.post.ts                                 
  - server/api/admin/tenants/[tenantId]/sources/[sourceId]/upload.post.ts               
  - server/api/admin/tenants/[tenantId]/sources/[sourceId]/sync.post.ts                 
  - server/api/admin/tenants/[tenantId]/jobs.get.ts                                     
                                                                                        
  内部流水线是：                                                                        
                                                                                        
  1. 管理员创建资料源                                                                   
  2. 资料源配置被转成统一 config
     通过 lib/source-config.ts                                                          
  3. 同步时根据 source type 选择 loader                                                 
     通过 server/lib/ingestion/load-source-documents.ts                                 
  4. 具体 loader 分三类：
      - 文件：server/lib/ingestion/sources/file-source.ts                               
      - 网页：server/lib/ingestion/sources/webpage-source.ts                            
      - IMAP：server/lib/ingestion/sources/imap-source.ts                               
  5. 导入任务执行器                                                                     
     server/lib/ingestion/execute-job.ts                                                
  6. 执行步骤是：                                                                       
      - normalize document                                                              
      - chunk                                                                           
      - embed                                                                           
      - save document/chunks                                                            
      - 生成 agent 文档包                                                               
                                                                                        
  这条链实际上又是一个完整系统：                                                        
                                                                                        
  source config -> loader -> normalize -> chunk -> embed -> repository -> job status -> 
  agent docs                                                                            
                                                                                        
  4. Agent 文档链路                                                                     
  这是你新增要求里单独生出来的一条链。                                                  
                                                                                        
  相关文件：                                                                            
                                                                                        
  - 生成器：server/lib/agent-docs/generate-agent-doc-bundle.ts                          
  - 渲染器：server/lib/agent-docs/render-agent-doc.ts                                   
  - 读写路径：server/lib/agent-docs/paths.ts                                            
                                                                                        
  当前行为是：                                                                          
                                                                                        
  1. 资料导入成功后生成：                                                               
      - AGENTS.md                                                                       
      - BOOTSTRAP.md                                                                    
      - HEARTBEAT.md                                                                    
      - IDENTITY.md                                                                     
      - SOUL.md                                                                         
      - USER.md                                                                         
      - TOOLS.md
  2. 文件落地到：                                                                       
     .data/agent-docs/<tenantId>/latest/                                                
  3. 后台支持读取和编辑：                                                               
      - server/api/admin/tenants/[tenantId]/agent-docs.get.ts                           
      - server/api/admin/tenants/[tenantId]/agent-docs/[fileName].put.ts                
  4. 前端管理面板：                                                                     
     components/admin/tenant-workspace/AgentDocsPanel.vue                               
                                                                                        
  这说明“导入系统”不仅负责入库，还顺带负责“知识表达层文档生成”。                        
                                                                                        
  5. 管理后台链路                                                                       
  当前租户后台页 pages/admin/tenants/[tenantId].vue 实际承担了非常多职责：              
                                                                                        
  - 租户基础信息编辑                                                                    
  - FAQ 沉淀                                                                            
  - 内容配置 JSON 维护                                                                  
  - source 管理                                                                         
  - upload/sync/job 管理                                                                
  - agent 文档编辑                                                                      
  - 账单摘要                                                                            
  - 会话/留资总览                                                                       
  - 安装配置                                                                            
                                                                                        
  也就是说，这一页本质上已经是一个“单租户运营控制台”，不是普通详情页。                  
                                                                                        
  配套页面还有：                                                                        
                                                                                        
  - 账单：pages/admin/billing.vue                                                       
  - 聊天：pages/admin/chats.vue                                                         
  - 留资：pages/admin/leads.vue                                                         
                                                                                        
  6. 存储链路                                                                           
  这是现在最值得你拿来判断“要不要拆项目”的点。                                          
                                                                                        
  当前存储其实是混合状态：                                                              
                                                                                        
  1. 传统 SaaS 数据：                                                                   
     通过 server/lib/storage/index.ts                                                   
     默认走 file store：                                                                
     server/lib/storage/file-store.ts                                                   
                                                                                        
     它保存：                                                                           
      - tenant                                                                          
      - session                                                                         
      - message                                                                         
      - lead                                                                            
      - usage                                                                           
      - tenant user                                                                     
      - reset code                                                                      
  2. RAG 数据：                                                                         
     走独立的 RagRepository                                                             
      - 接口：server/lib/repositories/rag-repository.ts                                 
      - Postgres 实现：server/lib/repositories/postgres-rag-repository.ts               
                                                                                        
     当前策略是：                                                                       
      - 如果有 CUSTOMER_BOT_DATABASE_URL，尝试走 Postgres                               
      - 否则走内存版 repository                                                         
  3. 原始文件资产：                                                                     
     落在 .data/source-assets/                                                          
  4. agent 文档：                                                                       
     落在 .data/agent-docs/                                                             
                                                                                        
  所以你现在的系统不是“一套统一存储”，而是：                                            
                                                                                        
  file-store + optional Postgres + local assets + local agent-docs                      
                                                                                        
  这已经明显显示出分层压力。                                                            
                                                                                        
  7. 构建与运行链路                                                                     
  当前构建/运行链有 3 条：                                                              
                                                                                        
  1. Widget 构建                                                                        
     npm run app:widget:build                                                           
     入口：src/widget.ts                                                                
  2. Nuxt/Nitro 应用构建                                                                
     npm run app:build                                                                  
  3. 运行验证脚本                                                                       
     现在有一组仓库内脚本：                                                             
      - verify:chat                                                                     
      - verify:chat-persistence                                                         
      - verify:ingestion                                                                
      - verify:agent-docs                                                               
      - verify:postgres-rag                                                             
      - verify:source-config                                                            
                                                                                        
  这些是为了替代当前环境里不稳定的 vitest worker 执行路径。                             
                                                                                        
  我的判断                                                                              
  如果你问我“要不要迁移成多个项目链条”，我会这样看：                                    
                                                                                        
  不拆也能继续做，但当前仓库已经同时承载了至少 6 种职责：                               
                                                                                        
  - Nuxt 页面应用                                                                       
  - 外部挂件 SDK                                                                        
  - 聊天运行时                                                                          
  - 资料导入/同步流水线                                                                 
  - RAG 检索系统                                                                        
  - Agent 文档生成与编辑                                                                
  - 账单/租户/用户管理                                                                  
                                                                                        
  这意味着它现在更像“一个项目里塞了多个子系统”，而不是一个边界清晰的应用。              
                                                                                        
  适合拆分的最小方案                                                                    
  如果要拆，我建议优先拆成 2 到 3 条，而不是一口气微服务化：                            
                                                                                        
  1. customer-bot-web                                                                   
     放：                                                                               
      - Nuxt 页面                                                                       
      - admin/tenant 页面                                                               
      - 对外 API 门面                                                                   
      - 挂件配置接口                                                                    
      - 聊天接口门面                                                                    
  2. customer-bot-worker                                                                
     放：                                                                               
      - source sync                                                                     
      - IMAP / 网页抓取                                                                 
      - chunk / embed                                                                   
      - agent 文档生成                                                                  
      - 调度任务                                                                        
  3. 可选：customer-bot-widget-sdk                                                      
     放：                                                                               
      - customer-bot.js                                                                 
      - 挂件 UI 与嵌入逻辑

  如果暂时不拆
  那至少建议你在当前仓库里逻辑上先按这三层继续收边界：

  - web/admin
  - chat-runtime
  - ingestion-worker-like modules

  并且尽快统一存储边界，不要长期停留在 file-store + in-memory rag + optional postgres 的
  混合状态。
