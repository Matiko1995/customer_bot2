# /tenant/chats 座席工作台页面原型结构与交互流

## 文档目标
把当前只读聊天页升级为“座席工作台”，满足：
- 左侧：会话列表
- 右侧：会话详情
- 支持接管、人工回复、恢复 AI
- 每个座席都能看到 AI 客服的历史会话

---

## 1. 页面定位

页面路径：
- `/tenant/chats`

当前定位：
- 聊天记录查看页

升级后定位：
- 租户子账户座席工作台
- 负责会话查看、接管、回复、状态切换

---

## 2. 页面布局

整体采用双栏布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部：页面标题 / 筛选 / 搜索 / 统计                         │
├───────────────────────┬──────────────────────────────────────┤
│ 左侧：会话列表        │ 右侧：当前会话详情                  │
│                       │                                      │
│ - 状态筛选            │ - 会话头信息                         │
│ - 会话列表            │ - 消息流                             │
│ - 未读红点            │ - AI/客户/人工/系统消息区分          │
│ - 当前座席            │ - 接管/恢复 AI/发送回复              │
└───────────────────────┴──────────────────────────────────────┘
```

宽度建议：
- 左栏：30%~35%
- 右栏：65%~70%

移动端建议：
- 先不做复杂适配
- MVP 保持桌面优先

---

## 3. 页面模块结构

### 3.1 顶部区域

包含：
1. 页面标题：`座席工作台`
2. 副标题：`查看 AI 会话、接管人工咨询、统一处理客户消息`
3. 快速统计：
   - 全部会话数
   - 待接管数
   - 我的会话数
   - 人工中会话数
4. 搜索框：
   - 搜客户名
   - 搜联系方式
   - 搜 visitorId / sessionId

### 3.2 左侧会话列表区

#### 顶部筛选 Tabs
- 全部
- 待接管
- AI中
- 人工中
- 已结束
- 我的会话

#### 列表项字段
每条会话卡片展示：
- 客户名（没有则显示 visitorId）
- 最近一句消息摘要
- 最后消息时间
- 状态标签
- 未读数红点
- 当前座席姓名（若已接管）

#### 状态标签建议
- AI中：蓝色
- 待接管：橙色
- 人工中：绿色
- 已结束：灰色

### 3.3 右侧详情区

由 3 个部分组成：

1. 会话头部信息
2. 消息流
3. 回复输入区

---

## 4. 右侧详情区详细结构

### 4.1 会话头部

展示：
- 客户名 / visitorId
- 联系方式
- 当前状态
- 当前座席
- 开始时间
- 最后活跃时间

操作按钮：
- 接管会话
- 恢复 AI
- 刷新

按钮状态：
- status='handover_requested'：显示“接管会话”
- status='human_active'：显示“恢复 AI”
- status='ai_active'：可显示“手动接管”或不显示

### 4.2 消息流

消息类型区分：

1. 客户消息
- 左对齐
- 简洁气泡
- 标识：客户

2. AI 消息
- 右对齐或中性样式
- 标识：AI
- 可继续保留 citations / 资料命中展示

3. 人工消息
- 右对齐
- 标识：人工客服 张三
- 颜色与 AI 消息区分

4. 系统消息
- 居中弱化显示
- 例如：
  - 客户请求人工服务
  - 张三已接管会话
  - 张三已结束人工服务，恢复 AI

### 4.3 回复输入区

包含：
- 文本输入框
- 发送按钮
- 当前模式提示

交互规则：
- `human_active`：可输入并发送
- 非 `human_active`：输入框禁用，提示“请先接管会话后再回复”

## 7. 页面交互流

### 7.1 默认进入页面

1. 调用 `/api/tenant/chats`
2. 加载左侧列表
3. 若存在 `handover_requested`，默认选中第一条待接管会话
4. 否则选中最近活跃会话
5. 调用 `/api/tenant/chats/:sessionId` 加载右侧详情

### 7.2 点击左侧会话

1. 设置 `activeSessionId`
2. 请求详情接口
3. 渲染完整消息流
4. 将 `unreadForAgent` 清零

### 7.3 客户请求人工后

1. 会话出现在待接管筛选中
2. 左侧列表状态变为“待接管”
3. 座席点击后可见接管按钮
4. 点击“接管会话”后切为 `human_active`

### 7.4 座席发送人工消息

1. 调用 `/api/tenant/chats/:sessionId/reply`
2. 发送成功后刷新右侧详情
3. 左侧最新摘要同步更新
4. 客户端轮询后可看到人工消息

### 7.5 恢复 AI

1. 座席点击“恢复 AI”
2. 调用 `/api/tenant/chats/:sessionId/release`
3. 状态切回 `ai_active`
4. 输入框禁用
5. 后续客户发消息重新走 AI 流程

## 8. 列表刷新与详情刷新策略

### 左侧列表
- 每 10 秒自动刷新一次
- 发送人工消息、接管、恢复 AI 后主动刷新一次

### 右侧详情
- 打开会话后每 5 秒刷新一次
- 当前会话切换时重建轮询
- 页面离开时销毁轮询

原因：
- 不引入 websocket，降低实现成本
- 先满足 MVP 可用性

## 9. 页面空态设计

### 左侧列表为空
文案：
- `当前还没有会话`
- `客户发起咨询后会显示在这里`

### 右侧未选中会话
文案：
- `请选择左侧会话查看详情`

### 无匹配搜索结果
文案：
- `未找到匹配会话`

## 10. 页面操作反馈

建议统一 toast / inline feedback：

1. 接管成功
- `已接管该会话`

2. 回复成功
- `发送成功`

3. 恢复 AI 成功
- `已恢复 AI 服务`

4. 接口异常
- `操作失败，请稍后重试`

## 11. 样式与视觉层次建议

### 左侧列表卡片
- 当前选中项高亮边框
- 待接管项可加入浅橙底，提高座席处理优先级
- 未读数使用红色圆点徽标

### 右侧消息流
- 客户 / AI / 人工 / 系统 四种消息必须视觉可区分
- 不建议继续只依赖 role 渲染颜色
- 应基于 senderType 决定样式

### 回复框
- 固定在底部
- 保持客服工具台连续操作体验

## 13. 对应接口关系

左侧列表：
- `GET /api/tenant/chats`

右侧详情：
- `GET /api/tenant/chats/:sessionId`

接管会话：
- `POST /api/tenant/chats/:sessionId/takeover`

发送人工消息：
- `POST /api/tenant/chats/:sessionId/reply`

恢复 AI：
- `POST /api/tenant/chats/:sessionId/release`
